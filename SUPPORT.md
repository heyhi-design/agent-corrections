# Support

## Questions and bugs

Open a new issue at
[`.../issues/new/choose`](https://github.com/heyhi-design/agent-corrections/issues/new/choose)
and pick the template that fits:

- **Something's broken?** Pick "Bug report."
- **Have a correction pattern you think belongs in the example registry?**
  Pick "Correction pattern proposal."
- **Not sure if it's a bug or a "how do I..."?** Open an issue anyway. We'll
  redirect if needed. There's no separate discussion forum yet.

Expect a first response within 5 business days.

## If you're running this in production

If your team is running corrections in production and finding patterns this
project doesn't document yet, that's usually a design question, not a bug
report. A registry that's outgrown a single file. A promotion workflow more
involved than one person's judgment call. Tiered write authority across a team
rather than a solo operator. HeyHi works with teams on the infrastructure
behind agent workflows, including the judgment calls a template can't make for
you. hello@heyhi.design

## If you work on a design system

Design system corrections capture the specific moments when generated output
drifts from your token architecture or component patterns: code, component
specs, layout suggestions. Load them at the start of each build session and
the drift stops compounding session over session. If your team is building or
maintaining a design system and generated output keeps drifting from your
tokens or component patterns in the same handful of ways, the same pattern
applies here directly. hello@heyhi.design

Both of the above are the same door. Say a little about what you're seeing and
